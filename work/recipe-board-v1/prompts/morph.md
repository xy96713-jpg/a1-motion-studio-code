## 连续系统与状态密度（对标 Opus 5.5，2026-11-02）

数据与结论见 docs/analysis/OPUS55-STUDY-20261102.md：高赞作品是一条开放 prompt 产出的**一个连续系统**——全章 8–12 个状态，图形、文字、空间轮流接替，约每秒一个可见变化；不是每拍一张图。

- 一章一个系统：状态在整章里连续变化（morph、裁切、机位、材质交替），不要每拍清空重画。
- 每拍 3–6 个事件：`{ at, kind: graphic|text|space, what }`；任意 1.8 秒要有一个可见变化；最后一件落在落幅上，尾巴停不超过 2 秒。
- 三条腿轮流：同一类事件不要连续超过两次；下一拍的第一件事要接着上一拍的落态。
- 自检：`designDensityErrors`（design-density.mjs，`briefErrors` 调用）查 `states`/`events`；没过不写预览。

## 模块要导出什么

- `DUR`：整章秒数，等于任务的 `total`。
- `beats`：和任务的 `beats` 一一对应、顺序相同，每项 `{ at, cam: { x, y, s }, move, camMove }`：
  - `at` 用任务给的 `at`，不能改；
  - `cam` 是画面中心对准的世界坐标和放大倍数，`s` 在 0.5–3 之间；
  - `move`、`camMove` 是元素和镜头的过渡秒数，可以不写（默认 1.1 和 1.4）。
  - 不写 `say`：字幕由系统另外打。
- `items()`：返回元素数组，每个元素有固定的 `id`、`kind`，以及可选的固定属性 `text`、`font`、`weight`、`squeeze`。基本的 `kind` 有四种（另外两种见后面）：
  - `glyph` / `label`：一段字；
  - `line`：一条线；
  - `box`：一个框。
- `pose(item, k, t, P, moves)`：返回元素在第 k 拍的样子（第 4 个参数是镜头参数 `P`，动效工具是第 5 个 `moves`；不用就别写）；返回 `{ alpha: 0 }` 表示不显示。可以用 `t`（秒）让它在一拍之内持续动。属性：
  - 字：`x, y, size, color, alpha, text, fill`（字底色）、`align`、`delay`（这拍开始后晚多少秒才动）、`z`（叠放顺序）、`screen`（为 true 时坐标是屏幕像素，不跟镜头走）；
  - 线：`x, y, x2, y2, width, color, draw`（0–1，画出多少）；
  - 框：`x, y`（中心）、`w, h, stroke, fill, width`。
- 可选 `bg(g, t, cam)`：画底。用了 3D 层（见下）时，`bg` 不能把整屏涂满，否则会盖住 3D 画面。
- 不写 `fonts`：字体由系统按项目的 lettering 和风格选（规则 30），模块里写的字体名都会被换成角色对应的那款。
- 可选 `fg(g, t, cam)`：画在所有元素之上（染色、暗角、颗粒、淡出、片名的故障效果）。

## 超出平面图解时可以用的能力

讲案件经过、地点分布、年表、证据这类段落时，画面常常需要真实地图、证据图片和立体的镜头。模板提供这些，用法如下。

**元素的另外两种 `kind`：**
- `image`：一张图。pose 给 `key`（用哪张图）、`x, y`（中心）、`w, h`（按 cover 裁切）、`alpha`，可选 `comp`（canvas 混合模式，比如 `'screen'`、`'multiply'`）、`filter`（canvas 滤镜，比如 `'grayscale(1) contrast(1.3)'`）、`rot`。
- `draw`：自己画。导出 `draw(g, item, pose, t, x, y, scale, images)`，在 pose 算出的屏幕位置 (x, y) 上用 canvas 画任何东西（图钉、卡片框、逐字出现的日期；字不垫底板）；`images[key]` 是图片。

**3D 层：**
- 导出 `async stage3({ THREE, st, P, data, images, kit })`：开场时搭一次 three.js 场景（`st.sc` 场景、`st.cam` 透视相机、`st.r` 渲染器）。不要 `import` three，用传进来的 `THREE`。
- 导出 `place3({ st, t })`：每帧摆相机和物体（t 是秒）。`kit.orbit(st.cam, [x, y, z], 距离, 仰角度数, 方位角度数)` 把相机放到目标点周围。
- 3D 画面在最底层，所有元素画在它上面。
- pose 里写 `at3: [x, y, z]`，元素就钉在这个 3D 点上，镜头动它跟着动；再写 `persp: d`，大小按"距离 d 时为原大"缩放。
- `kit.mapPlane(THREE, st, data.地图key, { paper, ink, building, relief, origin, widths })`：把一张地图素材画成纸面地图平放在地上（北朝 -z），返回 `{ mesh, material, toWorld(px, py) }`。`toWorld` 把地图像素坐标换成 3D 坐标，给 `at3` 用；`material.color` 可以用来整体染色、压暗。参数加 `extrude: true`（或 `{ scale, color }`）会把真实建筑轮廓拉成立体楼块（回形针那种斜俯的立体城市）：适合镜头压低掠过城市的远景；地面上印了字、平放了证据板的拍不要开，楼会把它们切开。

**平面、2.5D、3D 怎么选（`forms`，routing/forms.json，两部回形针 92 拍量出来：平面 83%、2.5D 5%、3D 13%）：** 一句话：**要读的用平面，地方和一堆东西用 2.5D，形状本身是重点才用 3D。**
- 平面（formFor: `read`）：数字、表格、比较、列表、时间线、家谱、定义、推理、标签——观众要读的都放平面上。
- 2.5D（formFor: `place` 地方、`quantity` 数量感、`object` 真东西）：斜放的地图（在哪）、斜着堆起的剪报卷宗（有多少、拖了多久）、滑进来的论文页（这是真文件）、斜扫的带子。字还是平的，立在外面（`planePoint`）。
- 3D（formFor: `shape` 形状、`structure` 结构、`object` 主角物件）：双螺旋、产品的机关（滤嘴的通气孔）、要站住的主角物件（Y 光柱、DNA 字块、老电视）。一章最多一个 3D 主体；它的部件要读时，展平回平面（unwind-3d-to-flat）。
- plan2 每一拍写 `form: 'flat' | '2.5d' | '3d'` 和 `formFor`，系统会查：没写或理由不在这一类里就不过；写了 3d 却没有 `stage3`、或者有 `stage3` 却没有一拍是 3d/2.5d，也不过。
- 不为了「高级」上 3D，也不为了「统一」把该 3D 的改平（用户 10-26：该 3d 就 3d）。

**先看对标怎么做，再选平面还是 3D：** 任务里有 `breakdown` 时，这几拍原片用的是什么形式就用什么形式：原片是平面的屏幕、卡片、表格、圆点家谱，就用平面（`type.flat`）；原片是立体模型（双螺旋、染色体），才用 3D。不要因为"讲原理"就默认 3D（paperclip-138：STR 概率、IBD、家谱、数据库全是平面，只有双螺旋是 3D）。

- `layout.archive(g, t, { at, end, ground, litAt })`：档案走廊，东西放进去的那一格亮红；返回 `into(k, from)` 给飞进去的东西定位（B33）。

**质感底（必用，除非原片这一刻就是纯色底）：** 图解不要摆在纯色暗底上（盲审第四轮：没过线的 10 拍里 8 拍是「黑底上的平面色块，像幻灯片」，原片同一处是纸、书页、桌面、胶片）。任务的 `grounds` 列出现成的无字实拍底板（`images.ground_paper` 纸面、`ground_pages` 摊开的空白书页、`ground_desk` 桌面、`ground_board` 档案板、`ground_folder` 卷宗、`ground_lightbox` 灯箱、`ground_concrete` 水泥墙、`ground_archive` 一排排无字卷宗盒的档案架：原片摆一排人或案子而文稿只点名几个时，用它撑起「一桩桩」的数量，不编人），代码里写到它的名字就会备好；用 `type.flat.plate(g, images.ground_xxx, { tone, push, dx })` 铺满画面（已按片子调成灰、暗、压角），图和字照常用代码画在上面。条、带、序列画成躺在底上的实物：`strip3d`（纸条/胶片条：有厚度、阴影、微斜）；一排人或案子用 `lineup`（横贯画面、镜头沿着走，红框只给正在说的那一个）；大数字用 `counter`（居中老虎机滚动后定住）；平面的条、卡、表要「放在桌上」时用 `onPlane(g, (q) => { …在 q 上画… })` 铺成近大远小的透视，字在外面用 `planePoint` 找位置立着排。检查会把每拍和原片同一时刻比「底有多平、红有多少、画面多满」，写在 warnings 里。

**现成的 3D 图形（原片用立体模型的地方用它们，别用细线自己画）：** 讲原理最常见的毛病是主体太小、挤在上半屏、只有几根细线（全片测试里平面画的原理章都只有 2–3 分）。所以讲序列、比例/筛选、家谱或上下级时，**默认搭 3D 层，用下面的图形当主体**，镜头贴近、斜着看、让它铺满甚至出画；任务里平面的 `example`（dna.js）只用来学动作和节奏，不要照它的平面画法。只有内容完全不是这三类、也不是地图时，才自己画平面图解，而且主体要占画面一大半。下面三种图形都是平放在桌面上的大物件，镜头（`camera3`）可以在上面推、俯、沿着它看，`type.groundType` 能把字印在它们表面，`at3` 能钉在它们的某个部分上。示例见任务里的 `exampleKits`。
- `kit.dots(THREE, st, { n, cols, paper, ink, accent, token })`：N 个样本排成网格（"随机抽 1000 人""1000 个里只剩 1 个"）。`token` 说清每个点**是什么**：`'person'`（人，默认）、`'file'`（案卷、案件）、`'tube'`（血样、样本）；只有数的东西不是人也不是物件时才用 `'puck'`（扁圆片）。`.keep(at, ids)` 让不在 ids 里的点从外往里依次变暗，`.light(at, ids)` 把剩下的点染成强调色并放大，`.part(i)` 是第 i 个点的 3D 位置。在 `place3` 里每帧调 `.update(t, moves)`。
- `kit.seq(THREE, st, { text, cell, paper, ink, accent, origin })`：一长条字母（DNA 序列、编码、一串记号），镜头顺着它看就是往远处延伸。`.mark(at, from, to)` 把第 from 到 to 个字母点亮并在下面画一道线，`.cell(i)` 是第 i 个字母的位置。每帧 `.update(t, moves)`。
- `kit.helix(THREE, st, { text, ink, accent, at: [x, y, z] })`：**由字母组成的 3D 双螺旋**（回形针讲 DNA 的做法），字母始终朝向镜头，转起来也读得清。`.twist(at, 0 或 1)` 在"平的梯子"和"双螺旋"之间变形（"碱基两两配对、一个挨一个排成长链、拧成双螺旋"就是先 `twist(0, 0)` 再 `twist(at, 1)`），`.spin(at, 速度)` 让它一直转，`.unwind(at, from, to)` 把一段解开摊平成能读的字母（推近看 STR），`.light(at, from, to)` 把一段染成强调色，`.cell(i)` 是第 i 对字母的位置。每帧 `.update(t, moves)`。讲 DNA、序列、碱基配对时，主体默认就是它，不要画平面细线螺旋。
- `kit.dna(THREE, st, { text, tilt, ink, accent, paper })`：**实体双螺旋**（照效果图做的：颗粒质感的珠串骨架、两段胶囊拼成的碱基对、背光勾边、空中的灰尘、远处没入暗处），讲 DNA 是什么、长什么样时用它当主角，比字母螺旋更像成片。`tilt` 让它斜穿画面。`.join(at)` 碱基对两半依次合上，`.twist(at, 0 或 1)` 梯子和螺旋互变，`.flatten(at)` 摊平成梯子，`.spin(at, 速度)`，`.light(at, from, to)` 把几对染成强调色，`.dim(at, from, to)` 让其余的退暗只留这几对，`.cell(i)` 是第 i 对的中心。要读出具体字母时才用 `kit.helix`。被追踪的那一对要选正对镜头的（大约每 10.5 对转一圈），螺旋少转，否则它会转到背面看不见。
- `kit.blockType(THREE, st, { glyphs: data.<key>, height, depth, at })`：**立体大字**（原片 B44 那种站在桌上的巨大 D N A，正面印网点）。字形是家用字体的真实轮廓：答案里写 `glyphs: [{ "key": "dna", "text": "DNA", "face": "House Sumikaku" }]`，系统从字体里取出轮廓放进 `data.dna`。返回 `letters`（每个字的左右和高）、`top(i, u)`（第 i 个字顶面上的一点，用来放标签）、`rise(at)`（字从桌面一个个升起）、`dim(at)`。不用时 `glyphs` 写 `[]`。
- `kit.particleType(THREE, st, { glyphs: data.<key>, height, count, letters: 'ATCG', at })`：**粒子字母组成的立体字**（原片约 300 秒那个由小字母 A T C G 填满的 3D「DNA」）。字形同 blockType（答案里要 `glyphs`），每个粒子是一个小字母；`fig.form(at, dur)` 从散开的一团飞拢成字，`fig.dim(at)` 压暗，`fig.turn(at, rate)` 慢慢转。效果总览：`work/recipe-board-v1/bench/particleType.png`。
- `kit.chromosomes(THREE, st, { items: [{ id, len }], cols, ink, accent, at })`：**立体的 X 形染色体**（带条纹），排成一排或几排。`.light(at, ids)` 把某几条染成强调色（23 对里那条 Y），`.dim(at, ids)` 让其余退暗，`.mark(at, id, from, to)` 标出一条上的一段（位点、遗传下来的片段），`.spin(at, 速度)` 慢慢转，`.part(id)` 是它顶端的位置。每帧 `.update(t, moves)`。讲染色体时用它，不要画平面短棒。
- `kit.tree(THREE, st, { rows, paper, ink, accent, origin, token })`：从上往下的几代人（家谱，或任何上下级；每个成员默认是一个小人 `token: 'person'`）。`rows` 是每一代的成员 `[{ id, of: 父辈 id, label }]`。`.path(at, ids)` 把这几个人连成的一条线依次点亮，`.node(id)` 是这个人的位置。每帧 `.update(t)`。
- **自己搭的立体物也要有质感**：`kit.solidMaterial(THREE, { color })` 是套件共用的哑光颗粒材质（边缘略亮，和 dna、点阵、家谱一样），`kit.kitLights(THREE, st)` 补上主光、轮廓光和补光；不要用 `MeshBasicMaterial` 的平面圆片和方块当主体（评审："黑底上的光滑圆盘，没有质感"）。
- 镜头对准一个图形不用自己算距离：`camera3` 的一格写 `{ at, fit: 'tree', fill: 0.8, elev, azim }`，系统按图形大小算出距离，让它占满画面的 fill（默认 0.8，大于 1 就是贴近、出画）。图形的名字默认是 `'dots'` / `'seq'` / `'helix'` / `'chromosomes'` / `'tree'` / `'map'`，同一种放两个时在参数里给 `name`。推近某个部分时照旧写 `look`（如 `tree.node('z')` 的坐标）和 `dist`。
- **字放在图形让出来的地方，不要压在图形上**：`draw` 的最后一个参数和 `fg` 的 `where` 有 `where.box('seq')`（这个图形此刻在屏幕上的范围 `{ x0, y0, x1, y1 }`）和 `where.free(['seq', 'dots'])`（这些图形旁边最大的一块空地 `{ x0, y0, x1, y1, w, h, side }`，已经避开了字幕区；图形铺满画面时给的是离它中心最远的四分之一块，`over: true`，字压在图上，用 type 的角色字、不加底板）。标题、数字、结论按 `free` 给的位置和大小排；镜头动了它跟着变。
- **字的位置让系统算（`where.place`）**（2026-10-23 用户：肯定能从代码上、数学上做好）：标签、数字、标题不再手写坐标，先画好它要避开的东西（图形、图片、3D 物体、大字），再 `const q = where.place({ w: 宽, h: 高, near: [想放的中心 x, y] })`，字放在 `q.x, q.y`（块的中心）；章节自己套了镜头缩放时传 `g`（`where.place({ w, h, near, g })`），用返回的 `q.lx, q.ly`（画布自己坐标里的中心，`q.lx0, q.ly0` 是左上角）。系统在画面里找离 `near` 最近、不压任何已登记东西（本帧已画的字、读得见的背景大字、图片、3D 物体的投影框）的位置；`q.clear` 为 false 说明没地方，改小字号或换 near。`where.free` 也会避开已画的字和背景大字。系统每 0.2 秒查一次字压字、字压图、字被 3D 物体挡一半、字出画，持续 0.6 秒以上就不过。
- **颜色只用任务的 `palette`**：底色是 `palette.bg`（2D 的 `bg` 和 3D 的 `st.sc.background` 都是它），字和图形用 `palette.ink`，只有被追踪的那一个东西用 `palette.accent`。不要自己另定底色，全片的卡片、空镜都按这套颜色走。
- 场景底色（`st.sc.background`）和图形的 `paper` 用同一个颜色，桌面就看不出边，不像一块板子。
- 几个图形放在同一张桌面的不同位置（`origin` 把它的某个像素点放到世界原点，用来错开），镜头从一个移到下一个，就是一章里连续变化的一张图。颜色用任务的 `palette`（`bg` 当 paper，`ink`，`accent`）。

**素材（答案里提需求，系统先准备好）：**
- 任务的 `context` 是片名和这一章前后几拍的口播：城市、年份常常在这一章开始之前就说了，要地图时从这里找地名。
- 真实地图：答案的 `maps` 里写 `{ key, place, pins, radiusKm }`。`place` 是城市或城区（比如"白银区, 白银市, 甘肃"），`pins` 是口播里提到、要标在图上的地点原话，`radiusKm` 一般 3–6。系统从 OpenStreetMap 取真实路网，在场景里是 `data[key]`：`{ w, h, major, mid, minor, service, rail, water, building, names, pins }`，其中 `pins[地点] = { x, y, found }` 是地图像素坐标。`found` 为 false 时，这个点没找到真实位置：要么不标，要么放在附近并让画面写明"示意位置"。**不要用代码画假的城市地图，也不要让生图画城市、街道、航拍或地图**（系统会打回）；讲一座城里发生的事，就用真实地图。
- 示意图片：答案的 `art` 里写 `{ key, prompt, transparent }`（最多 8 张），由生图模型画，场景里是 `images[key]`。只用来画示意的东西（指纹、鞋印、物件、质感），提示词用英文描述画面，不能要求图里有字、有真人的脸。用了示意图的画面，系统会在角上写"示意"。
- 已确认的真实素材：任务里的 `assets`（如果有）是用户确认过的照片，场景里是 `images[key]`，按 `what` 用在对应那一拍。
- 不需要的就写空数组：`"maps": []`、`"art": []`。

## 动效：用现成的动作，不要自己调缓动

`pose`、`draw`、`fg` 的最后一个参数和 `stage3` / `place3` 里的 `moves` 是一套调好的动作（曲线和时长都定好了，照回形针的开场调的）。你只决定**哪句话用哪个动作、在第几秒开始**：
- `moves.drop(t, at)` → `{ alpha, dy }`：标签、图钉从上方落到位，带一点回弹。
- `moves.pop(t, at)` → `{ alpha, scale }`：卡片、数字弹出。
- `moves.draw(t, at)` → 0–1：线、框、时间轴画出来。`moves.wipe(t, at)` → 0–1：图片从上往下擦出。
- `moves.flick(t, at, { seed })` → alpha：像屏幕捕捉到一样闪两下再稳住。
- `moves.push(t, at, until)` → 0–1–0：镜头推近一个细节、停住、再拉回；用 `moves.camBlend(远, 近, k)` 混两个机位。
- `moves.wash(t, at)` → 0–1：整个画面慢慢染色或压暗（全城染红、转暗）。
- `moves.glitch(t, at)` → `{ on, alpha, split, slices }`：标题故障闪入。
- `moves.type(t, at, text)`：逐字打出。`moves.count(t, at, 数值)`：数字跳到原文的数。
- `moves.stagger(i, at, gap)`：一排东西依次出现。
- **这一拍的字和标注留到拍尾**：标题、数字、结论要一直在，到下一拍开始（`beats[k+1].at`）才 `moves.fadeOut` 退场。提前退掉，观众还没读完，评审看的拍尾帧也就只剩空图形（全片测试里很多拍因此丢分）。
- **镜头调度（3D）**：导出 `camera3 = [{ at, look, dist, elev, azim, dur, ease }, ...]`，像动效师打关键帧一样写机位：每条从 `at` 开始移动、`dur` 秒后到位、然后停住（模板会叠一层很慢的呼吸）。`look` 可以是 `{ pin: '地点' }`（地图素材里这个地点的真实位置）、`{ map: [px, py] }`（地图上某个像素点）或 `[x, y, z]`。"推近一个地点、停住、拉回"就是三条：先远景，再 `{ at: 说到地点时, look: { pin }, dist: 小 }`，再 `{ at: 下一句, dist: 大 }`。写了 `camera3` 就不用在 `place3` 里算相机。
- **镜头不许甩**：系统逐帧量相机在屏幕上带动画面移动多少像素，任何一帧超过 48 像素（1920 宽；样板章 B07 最多 34）这一拍就不过，报错会写出这一段要多少秒。远距离换位置要给够时间（`dur` 加长，跨大半个场景通常要 2.5–4 秒；可以从上一拍的末尾就起步），或者少走一点。不要用 0.6 秒的快移去"过渡"。
- **一章是一个镜头，不切**（用户 2026-10-22："9 到 12 秒还是不自然硬切，明明能做动效贯彻好"）：`camera3` 里 `dur: 0`（或小于一帧）就是硬切，只有原片在同一时刻也切的地方才许用（系统按原片的切点核对，`cutErrors`）；章的第一格可以是起始机位。原片的一章是一镜到底的：
  1. **停—动—停**：每次运动慢起慢停，约 1–2 秒；动完停住给人读，下一次运动再起步。
  2. **眼睛先到，镜头再到**：要看的那个东西先亮起来、动起来（点闪一下、变红、长出来），镜头再移过去。
  3. **路上不清场**：移动途中，上一拍的东西还在画里，下一拍的东西已经在画里；不要先全部退掉再从空底上长出来。
  4. **换内容用变形，不用切**：地图沉进黑里、新底从黑里浮上来；同一个东西变大变小、换颜色、换排法。
  5. **一个运动只有一个主人**：镜头在动时，画面里的大东西不要也大幅度动；画面在大变时，镜头停着。
- 要用的小物件自己搭时，用 `kit.tokenGeometry(THREE, 'person' | 'file' | 'tube', r)` 拿现成的人、卷宗、试管，不要用圆柱代替。
- **设计巧思（plan2，必填）**：任务里有 `breakdown` 时，先读原片这几拍是怎么拆的（每个元素落在哪个字上、什么留到下一拍、用了什么手法、为什么）；`devices` 是手法库。模块必须导出 `export const plan2 = { carrier: '这一章跟着走的物件和它的变化链', beats: { <拍号>: { carryOver: '从上一拍留下来的是什么', devices: ['carrier', ...], form: 'flat' | '2.5d' | '3d', formFor: 'read' | 'place' | 'quantity' | 'object' | 'shape' | 'structure' } } }`。系统会检查：有 carrier；第一拍以后每拍都写了 carryOver（"全部淡出、全部淡入"不算转场）；devices 都在库里；至少用一个时间以外的手法。plan2 写的要在画面里真的做出来：carrier 物件在拍与拍之间只变形、移动，不消失重来；结论句用 scale-jump 之类的重音；开头的画面在结尾呼应。每个元素的出现时间按它在这一拍文字里的位置算，落在字上：直接用 `where.said('词')`（系统按台词算出这个词被说出来的秒数）。画面上的字只要是台词里的词，系统就量它第一次出现的时刻，早 0.8 秒以上或晚 1.2 秒以上就不过（`cueTimingErrors`）。例外是这一拍新出的名词：几个字、做成全屏最大的字（屏幕上 150 px 以上、6 个字以内），从这句话一开始就上屏，并留到下一拍开头，原片的 STR、IBD 都是这样；它的中文释义还是等说到再出（2026-10-25 整片审片：STR 晚了 6 秒，IBD 只闪了 1 秒）。
- **画面要压得住（系统量，不过就退回）**：这一拍文字里说到的数字，只要出现在画面上，最大的那一处至少 72 px（"8 次和 11 次"、"比到 15 个位点"做成 44 px 的小字会被退回）；每拍关键帧的下半部（字幕区以上）要有东西，下半部的内容少于三成就是画面挤在上半部（盲审两轮都说"下半部大片空着"，2026-10-23）。
- **逐项回答原片（follows，有 `breakdown` 时必填）**：`breakdown` 里每一拍的 `elements` 是原片这一拍画面上的东西（按顺序编号 0、1、2…）。plan2 这一拍要写 `follows: [{ el: 编号, does: 'match' | 'differ', how: '…' }]`，每个元素一条：`match` 写我们画面里怎么做到的；`differ` 写为什么不做（比如原片的数字我们的文稿里没有、不能编）。漏一个就不过检查。不许只做"大意"：原片先给一排很多位点再落到一个、拉远看见整条链、换成一张两轴图，这些都是元素，要么做出来，要么写清楚为什么不做（paperclip-138-full 2026-10-22：这几处 breakdown 里都写了，方案跳过了，都是用户看出来的）。
- **按旁白选手法（deviceCues）**：任务里的 `deviceCues` 是每一拍的旁白触发的手法（手法库每条的 `when` / `cue`：原片在旁白说同一类话时用的做法，例：「被称为」→ term-biggest 新名词最大；「只剩 / 确定 N 名」→ narrowing-frames 层层收框；「完全一致」→ symmetry 对称）。它只是从字面上猜的：在第二部片（回形针 Vol.047）上，必用手法被触发时，大约一半是对的。所以先看这句话在做什么，再挑手法：
  - 给一样东西命名 → 新名词最大；
  - 两样东西放在一起比 → 对称；
  - 一个数在变 → 数字一位位长；
  - 引一份研究或文件 → 真文献拎出原句；
  - 列举几样东西 → 引线或轮换。

  标了 `required` 的（term-biggest、narrowing-frames、symmetry）被触发时，plan2 要么用它或它的 `alt` 之一，要么在那一拍写 `declined: [{ device, why }]`，说清这句话为什么不需要它。两样都没有就不过检查。手法库本身换片子是通用的：Vol.047 用到的 102 次手法里，96 次库里已经有。
- **章节语言（没有对标片时也照它做）**：任务的 `language` 是从两部回形针 92 拍量出来的一拍的样子（`routing/chapter-language.json`，`chapterlang.mjs`）：一拍多长、出几样东西、隔多久出一样、元素卡着词出、动的帧占多少、最长停多久、同屏多少字几行、最大那行多大、画面多满、拍与拍之间怎么接。按中间那一半（p25–p75）定默认值，可以偏，但预览会逐拍按 p10–p90 两头量（`profile-gaps.json` 里写着 `language:` 的那几条：字太多、行太多、停太久、没有一行站得大、画面空），超出的那拍下一轮先改。文案和对标片不同时，按这把尺子做，不照搬原片的具体画面。
- **对标的硬指标**：预览会把这一章和原片同一段逐秒量一遍（`preview/profile-gaps.json`：在动的帧、停住的秒、画面上的字数、画面填充、红色）。量出来差得远的地方，下一轮先补。数字只拿这个项目自己的对标片来比，不要背别的片子的数字。拆过两部回形针（Vol.138、Vol.047，2026-10-22）以后看得出：
  - **两部片都一样的是节奏**：停一次中位 1 秒、九成在 3 秒内，动一次中位 0.9 秒；屏上中位 3 行、12 个字；字高中位 52 px；画面填满一半左右。这些可以当通用的底线。
  - **每部片不同的是样子**：硬切的密度不同（Vol.138 二十秒一个，几乎全靠变形转场；Vol.047 五秒一个）；在动的秒数不同（五成对九成）；亮度不同；红色的用量不同（65% 的秒里有红对 19%）。这些照这一章自己的对标片量出来的差距做，不要当成规矩。
- **一拍里不能停住太久**：元素落定后画面最多停约 6.5 秒（原片同一拍停得更久时，按原片那一拍的长度放宽），超过就判不过。在细线、小点、小字组成的稀疏画面里，加一根线、亮一个点、慢慢推近，量出来都几乎是"没变"。原片的做法（2026-10-22，B10 B18 B39 B47 四章因为这个被打回）：
  - 镜头跟着主体走：红点往上爬，镜头就贴近它一起爬；红线沿河画，镜头就沿河移；
  - 每加进一样东西，整幅画面重新构图：一代、两代、三代，家谱每多一列就整体左移一格；
  - 新的一处要放大到占满画面：下一个位点推近成大字；
  - 散乱的东西在说到"越长、越近"时归位排好。
- **物件上的字印在物件上**：生成的道具（试管、证件、卡片、屏幕）都留一块空白（标签、牌面），字由代码用 `type.printOn(g, 图, 中心x, 中心y, 长度, { turn, lines: [{ text }] })` 印进那块空白（深色墨、跟着物件转、吃物件的光），不要在物件上面另贴一个红签。生图的提示词里写明 "a blank white label"。
- **画面效果**：`fg(g, t, cam, moves, where)` 的 `where` 把点换成屏幕坐标：`where.pin('地点')`、`where.map(px, py)`、`where.project3([x, y, z])`。
  - `moves.spread(g, t, at, 点列表, { color, radius, alpha, comp })`：颜色从这些点向外扩散（全城染红从案发点蔓延开）；
  - `moves.ping(g, t, at, 点)`：一个点被标出时，一圈光环荡开；
  - `moves.glitchText(g, t, at, 文字, x, y, { font, color, track })`：片名、章节名故障闪入后定住。
- pose 里也可以写 `ease: 'back' | 'out' | 'expo' | 'linear'`，决定这一拍从上一拍变过来的曲线（默认先快后慢的 inOut）。

节奏规则（系统会量）：
1. **每拍一个主动作**，落在这句话最有分量的词说出来的时候（数字、地名、结果），其他东西安静地待着。
2. **不能冻住**：一拍里画面完全不动超过 2 秒就打回。模板已经让镜头一直在很慢地呼吸（轻微推拉和漂移），跟着镜头走的元素会自然动；但钉在屏幕上的（`screen: true`）不会动，所以别让一大块屏幕固定的面板在一拍里占满画面不动。需要整片静止时（比如片名）写 `export const drift = false`。
3. **动作做完要留出读的时间**：一拍的动作尽量在前半拍做完，后半拍只保留慢漂移，别让东西一直在跳。
4. 转章节、转情绪的时候用 `wash`、`glitch` 这类有意思的转场，不要每次都是淡入淡出。

## 字：按角色排，不加底板

`draw`、`fg` 的最后一个参数和 `stage3` / `place3` 里的 `type` 是一套字体角色（照 Gawx Art 的做法和用户选定的方向做的），字体已经自动加载。每一拍只用一种角色，大字和小字交替，大约每六拍最多一次大字事件：
- **陈述拍**（一个结论、一个数字、一个身份）：`type.grid(g, t, at)` 画出编辑网格，`type.serif(g, t, at, 文字, x, y, 字号)` 让高反差宋体落到网格上（主字 300–460，配字 120–160），`type.micro(g, t, at, 文字, x, y)` 打出一行极小的宋体，`type.aside(g, t, at, 'I.' 或年份, x, y)` 放 Didot 斜体的编号或年份。这时把地图压暗（`plane.material.color` 调到 0.3 左右），留出空白。
- **空间拍**（在哪里、散在哪、哪一个）：`type.groundType(THREE, st, plane, [{ text, at: [地图像素 x, y], size: 地图像素, kind: 'outline' | 'ink' | 'tracked' }])` 把字印在地图表面上，跟着透视走，返回的 `fade(a)` 在 `place3` 里控制出现；`type.hairline(g, t, at, 屏幕上的点, { big: '8', unit: '岁', small: '最小的一位' })` 从地点拉一根红色细线出去，弹出 Didot 数字、单位和一行小字。
- **不要给字加底板**：标题、标签、数字都不放在深色或彩色的方块上（系统会量，40 像素以上的字压在方块上就打回）。要读得清，就把背后的图压暗、留空白，或者用字本身的大小和颜色。
- 用了 `type` 就不用自己写字体名。**陈述拍的主字用 `type.serif`（高反差宋体），数字和年份用 Didot（`type.aside`、`type.hairline`）**；全片世界里的标题字体只用在片名和章节标题上，不用来排每一拍的陈述（用户 2026-10-20 选定：编辑网格 + 宋体 + 字印在地图上）。
- 一拍里只有一个主角字：结论或数字放大，其余退成一行极小的宋体；两个大字不要叠在同一处（比如数字和结论要分在不同时刻或不同格里）。

## 画面规则（系统会检查）

1. **不碰字幕区**：屏幕上 y > 935 的地方不放字（底部留给用户后期加的字幕；全线一个数，和排版圣经、家规一致）；字不能出画（左右各留 40 像素）。
2. **字要读得清**：每拍关键帧上要读的字，屏幕上至少 22 像素高（镜头放大后算）。
3. **数字只用原文的**：画面上的每个数字都必须出现在这一章的口播原文里。示意的东西（序列、点阵、形状）不带具体数字。
4. **颜色只用任务给的** `palette`（底、字、强调）加灰色；强调色只给这一拍最该被看到的东西。项目定了风格（任务的 `filmStyle`，来自 routing/styles.json）时，零件的颜色会自动跟着风格变（`type.flat.COL.red / ink / dim / grey / paper`），模块自己画的东西也从 `type.flat.COL` 取色，不写死 `#e8452c` 这类颜色——换一套风格整章要跟着变。生图（底板、道具）照 `filmStyle.art` 的画法写提示词。
5. **每拍都有变化**，而且回答这一拍口播里最有分量的那个词；前一拍的东西尽量留着、变形过去，不要换一张新图。
6. **素材只走答案里的 `maps`、`art` 和任务的 `assets`**：代码里不联网、不用 `fetch`、`import`、`eval`、`localStorage`、`new Image`；可以用 `document.createElement('canvas')` 做纹理。
7. 示意图不冒充真实数据或真实照片；地图、地点、日期这类事实只用真实地图和口播原文里有的。
8. **画面要满**：主体放在画面中部（y 在 200–820 之间），横向至少占画面的六成；不要把整张图挤在上半部。
9. **换拍不叠字**：上一拍的标题和标注先淡出（或者让新的晚 0.4 秒以上再出），新旧两行字不要在同一个位置重叠；标签不要压在序列或线条上。
10. **照全片的世界画**：任务的 `world`（如果有）是全片定好的底色、标题字体、纹理（颗粒、网点、暗角）和介质，这一章的底、字体、质感跟它一致；`palette` 是它的颜色。
11. **字不加底板**：见上面"字：按角色排"。
12. **字不压在卡片和物件上，标签之间不互相压**：大字落在一堆照片卡上、标签叠着标签，都会被退回（系统量：`crossErrors` 把卡片里的图也算进去，`overlapErrors` 量物件和物件互压）。标题出来时，卡片先让开、压暗或退到后面。
13. **很多件同类的东西，每件用不同的图**：十几起案子、一排样本、一摞档案，不要用同一两张图复制十几次（系统量 `repeatErrors`：同一张图一拍里最多 3 处），也不要把图拿掉只剩代码画的条和框（用户 2026-10-23："dna 怎么变得更简陋了，还不如之前的手印脚印"）。从共用物件库（任务的 `props`，`routing/props.json`）取同一族里不同的成员：2D 用 `K.props(images, 'trace', n)`，3D 直接写 `images.prop_trace_blood` 这类键；库里种类不够就往 `props.json` 加成员，不在一章里临时画。
14. **一件事只说一遍**：报道页上划出来的那句，不要再做成卡片把同一句话又写一遍。划线、放大、弹卡片，选一种。
15. **接着上一章的镜头走，不来回**：上一章刚推进去，这一章不要先拉出来再推进去（推→拉→推，看着像倒带）。读任务里上一章最后的画面，从它停的地方往前走。
16. **原片的比喻要保住意思**：原片用一个物件说一个意思（定时炸弹＝时间在倒数、迟早会响），生图不肯画时，用能画的部件拼出同一个意思（炸药管、导线、红色数码管分开生成），不要换成一个没有这层意思的东西。装饰性的读数（倒计时在跳、仪表在走）不是事实，用 `K.readout(g, cx, y, 字号, t, at, { from: 秒数, rate: -1 })` 画，数字一直在跑，系统不按原文核对它；但它不能说成某件事的真实数据（日期、人数、金额照旧用 label / counter，要有出处）。
17. **不留空框**：画中画、屏幕、纸面出现时，里面必须已经有东西；不要先出一个空的黑框、空的纸再往里填。原片是"框里放真实录屏"的地方，我们没有那段录屏，就不要学框，直接把内容做满全屏。
18. **原片克制的地方，我们也克制**：原片这一拍只有一个主体（一束光、一根染色体、一张脸），我们就不要堆 3D 模型和一排小人。先数原片画面上有几样东西，我们的不要多出一倍。
19. **原片在动的背景，我们的也要动**：标题背后的螺旋、地图、纹理，原片在转、在走，我们就不要放一张静止图。
20. **表格、表单、证件用生图做版式，字由代码填**：纸张、格线、印章、底纹用生图（不带字），格子里的字由代码写进格子，字号按格子大小来，不出格。
22. **已经在画面上的东西动起来要有起步**（2026-10-23 用户：小字一卡一卡 乱动）：「先快后慢」（out 曲线、`1 - (1 - k)³`）只给入场的东西用（它本来就从透明淡入）；已经停在画面上的字、图、整个画面的平移，用起步和收尾都从零速开始的曲线（`moves.CURVES.inOut`，或 `1 - (1 - s)³`，`s = k²(3 − 2k)`）。系统每 1/30 秒量一次每行字的位置，停着的字一帧走出 8 像素以上就不过（`hopErrors`）。`where.place` 的位置整章只算一次（检查时先把整章过一遍，选全程都最不挡的地方），不会跟着周围的东西跳。
21. **改一处，整拍再看一遍**（2026-10-23 一轮重做里，修好的地方旁边又冒出新硬伤）：撤掉一组元素，画面会不会空掉（B20 卡片撤光，只剩左上一块字）；把标签挪到边上，镜头推近后会不会出画（B48）；换到空地的字，会不会撞上背景大字或别的物体（B08 撞上 31.6 億，B23 的字被 3D 染色体的臂挡住）。3D 场景里物体挡字，系统量不出来，交之前自己看帧条。
23. **一拍的要点留到它最后一帧，交接放到下一拍开头**（2026-10-23 盲审 B09、B17、B33：把“交给下一拍”的动作放在这一拍最后一秒——第二条螺旋并走、证据卡飞走、档案缩成一个点——这一拍的最后一帧就没了它要说的事）：这一拍的东西停到拍尾；下一拍开头的第一秒再把它们合并、飞走、缩小。下一拍在别的章里，就在那一章的开头接住（比如 B10 开头让第二条螺旋并进第一条）。系统量每拍最后 0.35 秒的画面内容，少于它第三个四分之一段（较满时）的 60% 就不过（`seamErrors`，the picture empties before the beat ends）。
24. **字离画面边缘至少 24 像素，镜头移动时也一样**（2026-10-26 整片审片 B29：地名跟着镜头下摇，贴到画面上沿只剩 4 像素，像被切掉）：镜头要把字带到边上，就让字在那之前淡出（系统量 `textEdgeErrors`，连续 0.8 秒就退回）。
25. **图片不压强调色的块**（2026-10-26 整片审片 B44：家谱头像框随镜头滑到 IBD 红条上）：数据条、红签的底、标记各占一块，头像和照片不叠上去一截；红底托着照片可以（系统量 `coverErrors`）。
26. **该 3D 就 3D**（用户 2026-10-26：不用统一，该 3d 就 3d）：同一个东西（DNA、染色体）这一章用 3D、那一章用平面都可以，按这一拍要说的选；不要为了和前面一样把 3D 改成平面。只是不拿变色当转场（物件从灰变粉、从白变红来换意思），换意思就推近、展开、压暗或换构图。
