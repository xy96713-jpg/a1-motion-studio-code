# 定样子：三个锚镜的「无字目标帧」

> 这一步发生在整片设计之后、灰盒/章节之前。目标是**先把画面设计出来**，再写代码。不是再写一套风格权威；家规、TYPE 和用户批准的设计优先。

**先定载体。** 每个锚镜先写 `carrier`：`2d-diagram` / `2.5d` / `3d`，并写一句理由。默认 `2d-diagram`；`3d` 只有空间/遮挡/拆解/体积本身是内容时才用，且要写清“3D 增加了什么、2D 为什么不够”。整景 image-to-3D 不做（土块/多株/根/切面会糊成一坨）。

## 你要交什么

任务的 `input.anchors` 给出三个锚镜（`object` 实物/原理、`evidence` 证据、`map` 地图或数据）。每个锚镜交：

1. **2–3 个真正不同的方向**（A/B/C），每个是一张**无字目标帧** `directions[].file`：
   - 画面里不能有可读文字、数字、标牌、字幕；字由代码按 TYPE 后置。
   - 图可以是生图、Blender 渲染或引擎静帧；写清 `source`。
   - 方向要在**主体、构图、尺度、材质或光**上真的不同，不是同一张图调色。
2. **选中一个** `chosen`，写 `chosenWhy`：为什么这一张是这一镜要的。
3. `reference`：这张目标帧回答的参考帧（任务里给的 `input.references` 或本片参考帧）。
4. `achievable`：这一章用现有引擎、模型和素材怎么达到它；缺什么要先建（模型、Blender、生图底）。

返回 JSON 必须符合 `routing/lookdev.schema.json`，并把任务的 `inputHash` 原样写进 `sourceTaskInputHash`。

## 怎么做出顶级目标帧

- **先看参考**：打开任务给的参考帧，写清这一镜要继承的是哪一处关系（主体怎么站、尺度、机位、光、材质、留白），不是抄一张构图。
- **一镜一个设计**：目标帧要能回答「这一帧为什么值得看」。主体占画面 40–60%，有明确的第一阅读点，留白是设计出来的。
- **材料与光**：要有接触阴影、统一光向、真实粗糙度/颗粒；不要塑料感、平光、悬浮。实物主体要能看出厚度和重量。
- **3D 只在空间/遮挡/体积是内容时用**；2D/2.5D 能讲清就不要硬上 3D。
- **字位留出来**：目标帧无字，但要在 `chosenWhy` 里说明字将来站哪、占多大（按 TYPE 五档；标题该压场就压场）。
- **证据拍**：真实素材（截图、照片、页面）单独保真；生图只做无字的底、光和承载物，不冒充事实。
- **颜色**：按项目配色（`input.style` / `project.json style`），一条主色脊，点缀只给关键处；不要脏褐、不要用户否过的做法。
- **做得出来**：`achievable` 不许写空话。模型没有就写清用 partset/Hunyuan 先建；Blender 没做就写清 bake；素材没有就写清去哪找。

## 检查会拦什么

- 少于 3 个锚镜、或方向少于 2 个 / 多于 3 个；
- 目标帧带可读文字（`textFree` 不是 true）；
- 两个方向是同一张图（字节相同）；
- 文件不存在、不是图片；
- 没写参考、没选方向、没写 `chosenWhy` / `achievable`；
- `sourceTaskInputHash` 和当前任务不一致。

## 通过之后

`out/lookdev/lookdev.json` 是这三镜的目标帧与选择。灰盒、风格帧和章节必须按它做；章节答案的 `motionImplementation[].referenceComparison` 要绑定选中目标帧的文件和 sha256，并写清 start/change/end（`lookdevReferenceErrors` 会查）。章节偏离要在 `greyboxDiffer` 里写明理由。它不替代用户的设计关，也不自动批准任何东西。
