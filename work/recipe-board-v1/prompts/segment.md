# 段落分镜：把一段口播剪成一个整体

你拿到一段口播（逐字时间）、这段已确认的真实素材、全片的美学表（世界）。你要写这一段的段落脚本 `segments/<seg>.json`：一串首尾相接的镜头，每一刀切在说到那个词的时候，每一刀用下面一种处理。画面一律由引擎画（`engine`、`scene`），讲者和实拍用 `presenter`、`footage`。不要自己发明新的画法。

（用户 2026-10-20 定：画面只由引擎来做，美学是那套编辑网格宋体、Didot 数字、字印在表面上、不加底板、灰黑底一个红、真实材料放进 3D / 2.5D 空间；世界只调颜色和介质。）

## 时刻 → 处理

| 这一句在说什么 | 处理 | 写法 |
|---|---|---|
| 开场、某年某天、时间锚点 | 大字压在讲者上，或引擎的行情墙 | `presenter` + words（大字）；或 `engine` `ticker` |
| 引用报道里的事实 | 读报：真实网页平放进 3D，推到那一句，划线随口播走，数字浮起来 | `engine` `read`（params: src、crop、lines[{box, at, end}]、pull）|
| 一个吓人的数字 | 数字是主角：翻牌机、巨碑，或印在地面的大字 | `engine` `flipboard` / `monolith` / `number`，数字进 facts |
| 几家对比、排名 | 数据城市，或剪报横移 | `engine` `city`；facts 带全部数字 |
| 第一次叫出名字 | 真实 logo 落位，名字和中文名 | `engine` `name`（logo 用真实文件，不重画）；或 `nameplate` |
| 人物第一次出现 | 真实照片 + 姓名 + 一行身份 | `engine` `photo` |
| 讲原理、机制 | 一张连续变化的 3D 图解，真实材质，不画卡通小人 | `scene`（chapter，先在分镜里把这几拍定成 morph-chapter）|
| 讲经过、地点、年代 | 真实地图平放成 3D，镜头掠过，字印在地上 | `scene`（chapter，地图章）|
| 情绪、列举、夸张 | 真实素材快切，一刀 0.4–1 秒 | `footage` 连续几刀 |
| 作者判断、转折、提问 | 讲者推近，标签按词落下，不压脸 | `presenter`（或 `engine` `presenter`）|
| 原话 | 原话大字 + 人像 | `engine` `photo` + words |
| 一个问题、一章开头 | 一个大字（"凭什么"） | `engine` 的大字事件（type.serif），一章最多一次 |

还没进引擎的处理（`read`、`photo`、`number`、`name`、`presenter` 模块正在做）暂时可以用段落自带的 `article`、`print`、`name`、`word`，等引擎模块到了就换掉。

## 节奏

1. 切点 = 说到那个词的时刻（用逐字时间，不用整句）。一刀最多 6 秒；连续图解（`scene`）和引擎镜头最多 16 / 12 秒。
2. 快慢交替：列举和情绪处快切，结论和数字处停住；一段里讲者不超过四成，连续讲者不超过 5 秒。
3. 大字是事件：一段最多一两次，其余的字退成小字或干脆没有。
4. 镜头之间要接得上：数字从报道里浮起来、名字落进句子的空格、同一张图解前后变形、回到前面出现过的数字。不要每一刀都换一个新世界。

## 事实

- 画面上的每个数字都在 `facts` 里，`source` 是口播原文或已确认的存档来源（网页截图、论文）。
- 不写网站名、网址。logo、报道、照片、讲者都是真实素材，不生成、不重画。

只输出这一段的 JSON：`{ "about", "range": [起, 止], "cuts": [...] }`，系统先用 `checkSegment` 检查（首尾相接、长度、处理名、素材、数字来源），再由引擎渲染。
