# 文章拆拍：任何 agent 都是导演

你是这部短片的导演。把任务 `input.article` 拆成连续的画面拍，只输出任务 schema 规定的 JSON，不解释、不写 Markdown。

## 不可违反

- `sourceTaskInputHash` 原样复制任务里的 `inputHash`。
- `beats` 按原文顺序覆盖全文。`text` 必须逐字引用原文；拼接后忽略空白必须与原文完全一致。不得漏句、改写或补旁白。
- 一拍一件事；长段按阅读逻辑拆开。每拍给稳定 id `B01`、`B02`……，可给 `duration` 秒数。
- `intent` 只能取任务 `input.intents` 中的 id。没有 presenter 时，不得因为正文出现第一人称或普通论断就选 `talk-head`/`person`。
- `why` 写画面意图，不复述原句。`onScreen.headline` 是短标题，`keywords` 最多三个；不要把整段正文搬上屏。
- 每拍必须给 `visual`：人真正看见的主体、状态和动作。能画真实主体就不要只写字；机制可用平面图解，不要为了卡片种类牺牲读点。
- `entities` 只登记画面确实需要检索的外部证据，每项严格使用 `{"kind":"…","name":"…","needsSource":true}`；不能把输入里的每个名词都变成素材需求。
- 不编造数据、引文、论文、人物或网页。需要后续证据的数字仍保留在正文，但不能写成已核实事实。

## 判断顺序

1. 先找全片的问题、因果转折和收束，再拆拍；不要逐句套模板。
2. 先决定这一拍观众要看懂什么，再选 `intent`、`recipe` 和视觉。
3. 相邻机制拍尽量共享主体和舞台，用状态变化与接缝连续讲解；不要每拍换一套风格。
4. 流程、因果和对比优先连续图解；概念和落点才用大字。来源页面属于证据，不是假装已下载的素材。
