# 镜头拆解卡：把对标逐个小镜头拆细（手法、动效、设计、质感）

（用户 2026-10-21：拆的不够细，很多没对标上动效、设计。）系统已经量好了对标这一段：每个切点，以及两个切点之间的每个小镜头（R01、R02……）的机位（`camera`：`zoom` 推拉倍数，>1 推近、<1 拉远；`pan` 横/竖移动了几个画面宽，正数向右/向下；`moving` 动的时间占比；`ease` 前一半走完的比例，>0.6 先快后慢、<0.4 先慢后快）、画面（`look`：暗底/亮底、亮度 L*、彩度、颗粒）、画面上的字（`text`：OCR 读到的每行字、高度像素、中心位置；`display` 是最大的那行大字）、镜头里元素出现的时刻（`events`）。

你看每个小镜头的拆解图（三张：开头、中间、结尾，左上角写着编号、时间和实测的推拉平移），逐个写清楚：

- `device`：这个小镜头用的手法（和镜头导演的 `devices` 同一套：presenter 纯讲者 / side-card 讲者加卡或标签 / pagecurl / article / chat / table / compare3d / brand / broll 整屏照片或视频 / diagram / title / quote / person / recap / chart / screen / market 股价榜或 K 线等行情画面）。股价榜、K 线、走势图这类数据画面一律读成 market（由代码按真实数据画），不要读成 broll。系统拿它当对标的标准答案（旧的手法盘点是人眼粗看的，只做交叉核对）。
- `material`：这个小镜头用的真实素材种类（page 有字的页面 / photo 照片 / cutout 产品抠图 / portrait 人像 / logo 标志 / footage 视频 / none 没有，比如只有讲者和撕纸标签）。
- `shows`：画面上是什么（一句话：什么素材、什么内容）。纯讲者写"讲者中景，没有包装"。
- `layers` 的「底」要分清是**真实截图**还是**设计出来的底**：真的网页、报道、截图写「底：××网页截图」；设计的（说明卡/幻灯片式的白底面板加标志和要点、图标和放大镜的静物场景、拼贴、渐变色块）写「底：设计的说明卡……」「底：设计的静物场景……」，并写清里面有什么真实元素（标志、事实要点）。设计的底由生图画无字底图、真实标志和事实由代码排上去；把设计的底读成网页截图，导演就会拿网页顶上（开场 R20 曾把 DeepSeek 说明卡读成维基页）。
- `layers`：画面从底到顶分几层，每层是什么、在画面哪里、多大（例："底：股票行情屏截图，压暗、略虚；中：巨大金属字 2025年1月 居中占画面七成；顶：暗角＋颗粒"）。
- `type`：字的设计（字体气质：粗宋/黑体/手写/机械；粗细；字宽：瘦高/正常/扁宽；大小占画面多少；颜色和材质：白、黑、金属、描边；效果：色差、阴影、模糊；怎么进场：逐字、整体淡入、从模糊里出来、打字）。没有大字写 null；`display` 不为空时必须写（OCR 读到的其实是道具上的印字，比如麦克风、衣服上的字，写"无：麦克风上的印字"，这一项就不算）。
- `motion`：镜头和元素怎么动（推近/拉远/横移/竖移，多快，先快后慢还是匀速；元素怎么出现）。实测有推近（zoom ≥ 1.03）、拉远（≤ 0.97）或平移（≥ 0.04 个画面宽）的，必须写出来，系统会核对。
- `transition`：怎么切进这个小镜头（硬切、闪白、故障闪切、模糊过渡、推入……），第一个写它怎么开场。
- `texture`：质感（颗粒、暗角、色调冷暖、色差、纸张、印刷网点、景深）。

写的是你看到的，不是你打算怎么做；不确定的写"看不清"。之后镜头导演要逐项回应这张拆解卡（照做，或写明为什么不做），粗剪出来后系统再用同样的测量对比，没做到的拦下来不渲成片。
