# 挑素材：看缩略图，排出试的顺序

你拿到几条素材需求。每条一张对照表：第一格是对标原片同一时刻的画面（有的话），后面每格一个候选，左下角写着编号、来源、尺寸和标题；网页候选没有图，格子里是它的网站、标题和摘要。`what` 是导演要的东西，`entity` 是画面上必须是的人、产品或机构，`note` 是导演写的对标说明，`minWidth` 是铺满它的位置最少要多宽（像素）。

系统会按你给的顺序一个个下载，第一个被网站挡住、太小、不是要的东西，就自动换下一个，所以把能用的都排上，最好的排前面。

## 怎么挑

先分三类，不能混用：**真实的人、地、事、文件必须真素材；原理、机制、数字可用代码图解；氛围和无字承载物才可生图。** 具体人名、地名、事件名的中英文别名任一明确对上才算身份匹配；只有「城市、航拍、香蕉、烟雾」这类泛词对上是弱匹配，不因为画面好看就放行。

- 先看它是不是要的东西：要的是某个人就得是这个人，要的是产品就得是这个产品（不是别的型号、不是子产品），要的是一篇报道就得是那篇报道或同一件事的原发报道。
- **再看是不是那个时刻**：要「浮起来」就不能只是一张船停着；要「染病」就要看得见病症或明确的原始记录；要「历史证据」就不能用现代通用空镜冒充。视频优先选动作已经发生在素材里的时段，不靠后期推拉伪造事件。
- **最后看能不能成熟包装**：主体是否够大、轮廓是否清楚、景别和角度是否服务这句台词、有没有可用留白、焦点会不会和标题争抢、原生字幕/水印会不会被裁半截、调成本片颜色后是否还成立。真实但平淡、模糊、主体太小的素材仍然不选；灰度、颗粒、相框和大字不能救错素材。
- 报道：原发媒体排前（Fortune、Reuters、财新这类），转载站、聚合站（inkl、MSN、各种新闻搬运）排后；标题和摘要要说的是这件事，页面里能找到要读的原句。包装只标一次，不让原句、黑条和引语卡重复说三遍。
- 照片：像对标那样能铺满一屏、主体清楚的排前；示意图、零件特写、带水印的、截图里是别的东西的、明显太小的（尺寸小于 `minWidth`）不要。真实产品优先官方产品图；没有官方图且允许示意时才用明确标注的示意，不冒充实物证据。
- 视频：新闻片、纪录片原片排前；讲解类、反应类视频（一个人对着镜头说）不要。`why` 里写清可用时段和动作，不只写主题相关。
- 和对标比：不只比「是不是照片/网页」，还比同一语义时刻的主体尺度、第一阅读和包装空间。对标是一张满屏的照片，就别排一张小图标；对标是一页报道，就排报道页。
- **排序不是包装验收**：最佳候选先用实际像素做一张包装样帧，确认裁切、字位、介质和第一阅读成立再绑定。样帧不成立就换候选或改导演表达，不把失败归因给后期不够多。
- 一个都不像：`none: true`，`order: []`，`why` 写为什么（导演会换讲法或换模块）。宁可改表达，也不硬塞一条只是沾边的素材。

## 输出

```json
{
  "needs": [{
    "key": "meta-S2",
    "order": [1, 2],
    "none": false,
    "why": "1、2 都是原发且包装成立；3 是转载站",
    "assessments": [
      { "n": 1, "identity": "match", "moment": "match", "packaging": "viable", "why": "同一事件，主体够大，右侧留字位", "segment": null },
      { "n": 2, "identity": "match", "moment": "not_applicable", "packaging": "viable", "why": "同一文件，原句清楚", "segment": null },
      { "n": 3, "identity": "weak", "moment": "weak", "packaging": "weak", "why": "转载且主体不符", "segment": null }
    ]
  }]
}
```

`order` 中每个候选必须恰好有一条 assessment，且只能是 `identity: match`、`moment: match/not_applicable`、`packaging: viable`。视频还必须给 `segment: {start,end}`，时段在源时长内。weak/wrong 候选可留作比较，但不能进入 `order`。
