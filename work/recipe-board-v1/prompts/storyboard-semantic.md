# 规则：先拆语义，再挑手法（六段流程的分镜，接在 storyboard.md 之前读）

用户 2026-10-26：「导演有根据文案拆分好语义最好 想好怎么设计吗」「先规范 梳理最优方式执行」。

分镜不是先挑卡片。专业导演拿到一句话，先问**这句话在做什么**，再想**用什么手法把这件事做成画面**，最后才决定用哪张卡、镜头怎么走。每一拍按这个顺序写：

## 1. 这句话在做什么（`act`）

从 `routing/semantic-acts.json` 里选一个，一拍一个，选最主要的那件事：

提问、指出现象、命名、比例、规模、机制、比较、列举、推进、原因、转折、反转、证据、定性、后果、留白、收尾。

一句话里有两件事（先命名再给规模），两件都要记住时先拆成有先后的视觉事件；可以在同一原文拍中连续表现，也可以在有明确理由时切镜。不要为了适配事件而删除原文信息或机械增加旁白拍。

## 2. 用什么手法（`devices`，1–3 个）

从 `routing/devices.json` 的 56 种手法里挑，优先用这个语义动作推荐的那几种（`semantic-acts.json` 每条的 `devices`）。比如：

- 指出现象「香蕉都一模一样」→ 复制=重复（一根复制成一排）、一排人并列；
- 比例「约 47%」→ 一点一个人（100 根里 47 根亮起）、横条长度=比例；
- 机制「靠吸芽一棵分一棵」→ 一个东西分出几支、拆开看里面；
- 规模「3 万公顷」→ 数字长出来、一针一个；
- 推进「不同时间、不同地点的发现」→ 用有来源的地点和时间组织证据；只有来源支持传播路径时才画路径；
- 反转「同样是克隆」→ 前面的素材回来、首尾呼应；
- 定性「国家紧急状态」→ 结论横幅/盖章、真文献拎数字。

`deviceWhy` 一句话写清这几个手法怎么把这句话做成画面。用了不是这个动作推荐的手法，要在这句里说为什么。

## 3. 台词触发的手法要回应

任务里每拍的 `cues` 是台词里的词触发的手法（比如有「%」就触发「数字长出来」）。触发的手法要么用上，要么写进 `declined`（`{ device, why }`，一句理由）。触发只是从词猜的，猜错了就拒绝，说清楚为什么。

## 4. 手法要有变化

同一个手法不连着用三拍；一部片里任何一个手法不超过全片拍数的三分之一。全片的主手法（贯穿物、母题）除外，它在简报里已经定了。

## 5. 然后才是卡片和镜头

手法定了，再按 `storyboard.md` 选卡（连续图解还是卡片模块）、写主动作、镜头、读懂节奏。卡片和图解都要做出这一拍写的手法：章节代码的 `plan2.beats[B].devices` 要包含分镜写的手法（不用就写 `declined` 和理由），定样子挑的画面也照这些手法做。

答案的格式是 `routing/storyboard.v3.schema.json`（`contract: A1RecipeBoardStoryboard/v3`），每拍多了 `act`、`devices`、`deviceWhy`、`declined`。
